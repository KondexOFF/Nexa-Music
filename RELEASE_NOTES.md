# NEXA Music 1.1.1 — Windows x64

Личный музыкальный плеер для Windows 10 / 11 x64. Portable-сборка: папку `NEXA_Music_1.1.1_Windows_x64` можно положить в любое место и запустить `nexa_music.exe`. Установка не нужна, среда выполнения Visual C++ лежит в папке.

## Новое в 1.1.1 — NEXA Update Center

Следующие версии NEXA (первая — 1.2.0 Nocturne) устанавливаются прямо из программы.

- **Проверка обновлений:**
  - автоматически при запуске, не чаще раза в сутки; отключается в Settings → About;
  - вручную — кнопка «Check for updates» в Settings → About;
  - черновики и пре-релизы GitHub не предлагаются.
- **Уведомление** о новой версии с четырьмя действиями: «Update now», «What's new», «Later», «Skip this version». Ничего не ставится само: только по вашему нажатию.
- **Загрузка с прогрессом и проверкой:**
  - контрольная сумма SHA-256 берётся из данных GitHub о файле релиза и сверяется с `SHA256SUMS.txt`;
  - релиз без контрольной суммы не устанавливается;
  - архив проверяется до распаковки: абсолютные пути, `..`, ссылки, дубли имён, конфликты файлов и папок, CRC-32;
  - распаковка — во временную папку вне папки программы, затем сверка каждого файла со списком пакета.
- **Безопасная установка после закрытия NEXA** — «Restart and install» сейчас или «Install when I close NEXA»:
  - отдельный установщик ждёт, пока NEXA закроется;
  - сохраняет текущую версию;
  - заменяет папку программы;
  - запускает новую версию и ждёт подтверждения, что она работает.

  Если новая версия не запустилась, прежняя возвращается и запускается автоматически.
- **Откат** — «Roll back to …» в Settings → About.
  - Если новая версия уже обновила базу библиотеки, NEXA сначала объясняет это и спрашивает подтверждение. Затем возвращается копия базы, сделанная перед обновлением.
  - Текущая база при этом сохраняется отдельной копией, которая не удаляется автоматически. Новые плейлисты и история не теряются.
- **Библиотека, история, плейлисты и настройки** хранятся в `%APPDATA%\com.kondexoff\nexa_music`. Обновление их не трогает. Перед миграцией базы автоматически делается копия.
- **NEXA 1.1.1 никогда не открывает базу от более новой версии.** Вместо этого она предлагает вернуть копию из резервных; текущая база сохраняется.
- **Приватный репозиторий:**
  - доступ идёт через ваш авторизованный GitHub CLI (`gh auth login`);
  - NEXA не хранит, не видит и не пишет токены — ни в базу, ни в код, ни в логи;
  - без авторизации локальная музыка работает как обычно, в Settings видна понятная причина.
- **Понятные ошибки:** нет сети, нет GitHub CLI или входа, нет доступа к приватному релизу, лимит GitHub, повреждённый архив, нет места на диске, сбой запуска и откат.

## Обновление с 1.1.0

Версию 1.1.0 обновите вручную один раз: распакуйте 1.1.1 и запускайте её. Данные подхватятся сами, схема базы не меняется (4). Следующие версии ставятся уже через NEXA Update Center.

## Известные ограничения

- Папка программы после обновления сохраняет прежнее имя (например `NEXA_Music_1.1.1_Windows_x64`), чтобы ярлыки продолжали работать. Версия видна в Settings → About.
- Для самостоятельной замены файлов у NEXA должен быть доступ на запись к своей папке. Если доступа нет, NEXA предложит скачать новую версию с GitHub вручную.
- Установщик — скрипт Windows PowerShell, входящий в сборку. Если политика компьютера запрещает PowerShell, установка не начнётся; текущая версия остаётся нетронутой.
- Остальные ограничения 1.1.0 сохраняются:
  - YouTube: без своего ключа Data API нет поиска и истории; crossfade, фоновое воспроизведение и скачивание невозможны по условиям YouTube;
  - SoundCloud: звук только в официальном виджете, поиска внутри NEXA нет;
  - Smart Mix анализирует только файлы библиотеки;
  - блокировка рекламы обновляется вручную;
  - теги WAV в кодировке Windows-1251 читаются неверно;
  - для Jamendo нужен свой client id.
- `nexa_music.exe` не подписан: при первом запуске Windows SmartScreen может предупредить («Подробнее» → «Выполнить в любом случае»).

Проверка: `reports/RELEASE_1.1.1_READINESS.md` в репозитории.
