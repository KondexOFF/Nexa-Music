# E2 — YouTube в NEXA Music (Windows): feasibility gate

Дата: 2026-10-26. Основание: CR-001 (одобрен 2026-10-19), D-017, `ARCHITECTURE.md` (раздел «YouTube feasibility gate»), задание владельца 2026-10-26.
Статус: **исследование завершено, решение за владельцем.** В приложение YouTube-код не добавлялся; опубликованный релиз 1.0.0 не менялся; E3 и E4 не начинались.

## 1. Вывод

**Условно реализуемо (GO с условиями).** Официальный способ существует и подходит под CR-001:

- плеер YouTube IFrame Player API, видимый, внутри окна NEXA, в Microsoft Edge WebView2;
- поиск через YouTube Data API v3 с собственным ключом владельца или вставка ссылки без ключа;
- выдача YouTube отдельной секцией в Discover, рядом с Audius, Jamendo и библиотекой, а не вперемешку с ними.

Документы подтверждают допустимость подхода. Пять технических рисков (раздел 7) документацией не снимаются, их надо проверить на коде. Поэтому рекомендую: **сначала одобрить короткий прототип E2.0**. Это отдельная локальная ветка с минимальным экраном, ничего из неё не попадает в продукт. После прототипа будет окончательное решение «да / нет» по полной интеграции E2.1–E2.5.

Если прототип не пройдёт, запасной вариант по CR-001 — открывать видео YouTube в браузере, без встроенного плеера.

## 2. Что разрешено и что запрещено (актуальные правила)

Источники: YouTube API Services Developer Policies, Required Minimum Functionality, IFrame Player API Reference и Data API Overview (все обновлены 2026-10-15), руководство Developer Policies Guide.

| Тема | Правило YouTube | Что делает NEXA |
|---|---|---|
| Видимость и размер | Плеер не меньше 200×200 px, рекомендуется не меньше 480×270 для 16:9, элементы управления видны полностью | Плеер 16:9, не меньше 480×270 (при минимальном окне NEXA 1024×640 помещается) |
| Наложения | Нельзя ничего показывать поверх плеера или его элементов; нельзя действовать по наведению мыши | Плеер в отдельной панели, без наложений, тултипов и затемнения поверх; рамка NEXA только снаружи |
| Изменение плеера, реклама | Нельзя менять, достраивать или блокировать плеер; нельзя трогать рекламу (III.I.5–6) | Стандартный плеер с элементами управления и брендингом YouTube; реклама показывается как есть |
| Фон и аудио | Нельзя играть в фоне, в том числе в свёрнутом или закрытом окне (III.I.9); нельзя отделять аудио (III.I.7–8) | При сворачивании окна и уходе со страницы плеер ставится на паузу; звук идёт только из видимого плеера и никогда не проходит через `PlaybackEngine` или Mix Engine |
| Скачивание, кэш | Нельзя скачивать, кэшировать и хранить копии аудио и видео, нельзя офлайн (III.E.1) | Ничего не сохраняется; WebView2 использует собственный обычный кэш браузера |
| Автозапуск | Не начинать воспроизведение, пока плеер не виден; одновременно автозапуск только у одного плеера | Запуск только по нажатию пользователя на открытом экране плеера; один плеер |
| Идентификация клиента | Плеер требует заголовок `HTTP Referer` с идентификатором приложения (`https://<reverse-DNS app id>`), стабильным между версиями; без него ошибка **153** (с июля 2025) | Страница плеера отдаётся из WebView2 с виртуального хоста `https://com.kondexoff.nexamusic/` (в `SetVirtualHostNameToFolderMapping`); Referer = этот адрес; параметр `origin` тот же — **проверить в прототипе** |
| Вложенные iframe | Нельзя прятать плеер во вложенных iframe (III.I.21) | Страница WebView2 сама создаёт плеер через IFrame API, без дополнительной вложенности |
| Смешивание с другими источниками | Нельзя подавать чужие результаты как результаты YouTube; атрибуция у каждого результата, не одна на всех (III.C.5, III.F.2); рядом с другими платформами можно, если ясно отмечен источник | Отдельная секция «YouTube» в Discover со своей пометкой; каждый результат помечен; YouTube не вливается в списки Audius, Jamendo или библиотеки |
| Производные данные, рекомендации | Нельзя создавать из API Data новые или производные данные и метрики (III.E.4.h); нельзя выводить интересы пользователя без согласия | YouTube **не участвует** в NEXA DNA, Wave и истории (также требование CR-001) |
| Хранение API Data | Не более 30 дней, затем удалить или обновить; показывать актуальные данные (III.E.4) | Результаты поиска только в памяти на время сеанса. Ссылки YouTube в локальных плейлистах в первой версии не сохраняются (см. раздел 6) |
| Ключ и квота | Ключ через Google Cloud Console, один проект на клиент; нельзя встраивать ключ в открытый код (III.D.1); по умолчанию **100 вызовов `search.list` в день**; больше квоты — через аудит | Ключ владельца вводится в Settings и хранится только локально (как client id Jamendo). Поиск по Enter, без поиска по мере ввода. Без ключа работает вставка ссылки |
| Политика конфиденциальности | Ссылка на Условия YouTube; пользователь соглашается с политикой до использования; политика упоминает YouTube API Services и ссылается на Политику конфиденциальности Google (III.A.1–2) | Перед первым включением YouTube — экран согласия: что используется, что хранится (только ключ), ссылки на YouTube Terms of Service и Google Privacy Policy, как удалить ключ |
| Учётные записи | Нельзя запрашивать или хранить логины | Без входа в Google: только публичный поиск и воспроизведение |

## 3. Технические возможности Windows

| Вопрос | Находка | Вывод |
|---|---|---|
| WebView2 Runtime | Встроен в Windows 11 (Evergreen) | Есть у владельца; для других ПК — понятное сообщение и ссылка на установку, если нет |
| Flutter-пакет | Официальный `webview_flutter` не поддерживает Windows. `webview_windows` (jnschulze) — последняя версия 0.4.0 (февраль 2024), фактически не развивается. `flutter_inappwebview_windows` — 0.6.0 (октябрь 2024), 0.7.0 ещё beta. `webview_flutter_windows` (tomars.tech, форк jnschulze) — 1.3.0 (сентябрь 2026), поддерживается; есть виртуальные хосты, двусторонние сообщения JS ↔ Dart, события полноэкранного режима; рендер в Flutter `Texture`, без «окна поверх окна» | Кандидат — `webview_flutter_windows`; запасной вариант — `flutter_inappwebview_windows`. Сторонний пакет — риск сопровождения, поэтому он скрыт за адаптером `platform/youtube_embed` (CR-003) |
| Рендер через Texture | WebView2 не имеет официального off-screen API; кадры захватываются через Windows.Graphics.Capture | Проверить в прототипе: плавность видео, нагрузку на CPU и GPU, отсутствие рамки захвата |
| Медиаклавиши и медиапанель Windows | NEXA уже регистрирует свою сессию SMTC; Chromium в WebView2 может создать вторую. Флаг `HardwareMediaKeyHandling` есть, но Microsoft не рекомендует флаги для продакшна | Проверить в прототипе. Ожидаемое решение: пока YouTube играет, сессия NEXA показывает «на паузе»; клавиши обрабатывает активная сессия; флаги не используются |
| Команды плееру | IFrame API: `playVideo`, `pauseVideo`, `seekTo`, `setVolume`, события `onReady`, `onStateChange`, `onError`, `onAutoplayBlocked` | Достаточно, чтобы NEXA ставила YouTube на паузу и узнавала его состояние |
| Ошибки плеера | 2 — неверный id; 5 — ошибка HTML5; 100 — видео удалено или приватно; 101/150 — владелец запретил встраивание; 153 — нет идентификации клиента | Каждая ошибка → понятный текст и кнопка «Открыть на YouTube» (в браузере) |
| Ошибки Data API | Квота исчерпана, неверный ключ, офлайн | «Дневной лимит поиска исчерпан — вставьте ссылку», «Проверьте ключ в Settings», «Нет сети — библиотека работает» |

## 4. Архитектура

```text
features/discover/                     Discover: секция "YouTube" рядом с Audius / Jamendo
  youtube/youtube_search.dart          Data API v3 search.list / videos.list (ключ владельца)
  youtube/youtube_link.dart            разбор ссылок youtube.com/watch, youtu.be, /shorts, /embed
features/youtube_player/               экран плеера (видимый, без наложений)
  youtube_player_page.dart             страница: плеер 16:9 + название, канал, "Открыть на YouTube"
  youtube_player_controller.dart       состояние (ready / playing / paused / ended / error), команды
platform/youtube_embed/                адаптер WebView2 (CR-003: другие платформы - позже)
  windows_youtube_embed.dart           webview_flutter_windows, виртуальный хост, сообщения JS <-> Dart
  assets/youtube/player.html           страница с официальным IFrame API (без своих элементов поверх)
core/playback_arbiter.dart             "играет ровно один": NEXA PlaybackEngine или YouTube
```

Правила:
- YouTube **не** является `MusicSource` для `PlaybackEngine`. Возможности источника: поиск — да; воспроизведение — только встроенный официальный плеер; Mix Engine — никогда; история, DNA и Wave — никогда; хранение — только ключ.
- `PlaybackArbiter`. YouTube перешёл в playing → `PlayerController.pause()`. NEXA начала играть → `pauseVideo()`. Одновременно звучит только один источник.
- Видимость. Уход со страницы плеера, сворачивание окна или потеря видимости (`AppLifecycleState.hidden` / `paused`) → `pauseVideo()`. Закрытие страницы → плеер уничтожается.
- Нижняя панель плеера NEXA, пока играет YouTube, показывает «Сейчас на YouTube: <название>». Кнопка Play/Pause на ней работает только при открытом экране плеера (это команда IFrame API). Next, Prev и Mix недоступны и объясняют почему.
- Ключ Data API хранится в локальной базе (как client id Jamendo), не попадает в репозиторий, логи и отчёты.

## 5. UX (описание макета)

1. **Discover.** В строке фильтров появляется чип «YouTube» (рядом с All, Audius, Jamendo). При поиске — отдельная секция «YouTube», ниже Audius и Jamendo, с заголовком и пометкой «Поиск YouTube»:
   - строка результата: миниатюра (не меньше 120×70), название, канал, длительность, значок YOUTUBE;
   - кнопки «Смотреть в NEXA» и «Открыть на YouTube»;
   - если ключа нет: «Поиск YouTube выключен — вставьте ссылку или добавьте ключ в Settings», и поле «Вставьте ссылку YouTube».
2. **Экран плеера YouTube** (новая страница, открывается из результата):
   - сверху «← Назад»;
   - по центру панель NEXA с плеером 16:9 (от 480×270, растёт с окном, без элементов поверх);
   - под плеером название, канал, «Открыть на YouTube», строка «Видео YouTube. Воспроизводится официальным плеером; не попадает в историю и NEXA Wave»;
   - справа ничего не перекрывает плеер, правая панель NEXA на этом экране свёрнута.
3. **Settings → Online catalogs → YouTube.** Переключатель «Использовать YouTube» (по умолчанию выкл.) открывает экран согласия (раздел 2). Там же поле «Ключ YouTube Data API (необязательно)», ссылки на условия и счётчик «поиск: лимит Google — 100 запросов в день».
4. **Нижняя панель.** Пока играет YouTube — значок YOUTUBE и название; управление только с экрана плеера.
5. **Дизайн.** Палитра и шрифт NEXA; плеер YouTube остаётся в своём оформлении. Логотип YouTube не используется в брендинге NEXA, только как обозначение источника по Branding Guidelines.

## 6. Ограничения (честно)

- Без свёрнутого и фонового воспроизведения: свернули окно — пауза. Это правило YouTube, а не недоработка.
- Без Gapless, Crossfade, Smart Mix, без очереди NEXA и автоматического «следующего» между видео YouTube в первой версии.
- Без NEXA Wave, DNA, истории и лайков для YouTube.
- Без сохранения YouTube в плейлисты NEXA в первой версии: хранение ссылок требует обновления или удаления через 30 дней. Это можно сделать позже отдельным пунктом.
- Поиск только с ключом владельца, около 100 поисков в день; без ключа — только вставка ссылки.
- Некоторые видео запрещают встраивание (101/150) — для них только «Открыть на YouTube».
- Реклама YouTube показывается как есть.
- Зависимость от стороннего Flutter-пакета WebView2 и от WebView2 Runtime. Portable-папка вырастет на загрузчик WebView2 (`WebView2Loader.dll`) и плагин.

## 9. Критерии приёмки E2 (предложение)

1. Видео запускается только по действию пользователя, в видимом официальном плеере не меньше 480×270, без наложений; реклама и брендинг YouTube не изменены.
2. Сворачивание окна, уход со страницы и закрытие страницы ставят YouTube на паузу или останавливают его; фонового звука YouTube нет.
3. NEXA и YouTube никогда не звучат одновременно; переключение в обе стороны ставит другой источник на паузу.
4. Нет ошибки 153; ошибки 2, 5, 100, 101/150, офлайн, квота и неверный ключ показывают понятный текст и «Открыть на YouTube».
5. Результаты YouTube — отдельная помеченная секция; YouTube не попадает в Wave, DNA, историю и плейлисты NEXA.
6. Аудио YouTube не идёт через `PlaybackEngine` и Mix Engine; нет скачивания, извлечения, скрытого плеера, обхода рекламы и неофициальных адресов.
7. Без ключа работает вставка ссылки; ключ хранится только локально, его нет в репозитории, логах и отчётах.
8. Локальная библиотека, Wave и Audius / Jamendo работают как раньше (AutoTest и регрессия); Portable-сборка запускается.
9. Экран согласия с условиями YouTube и Политикой конфиденциальности Google показан до первого использования.

## 10. Что нужно решить владельцу

1. Одобрить прототип E2.0 (риски R1–R5) — да / нет.
2. Пакет WebView2: `webview_flutter_windows` (рекомендую) или `flutter_inappwebview_windows`.
3. Поиск YouTube через собственный ключ Data API (создаёт владелец в Google Cloud) — или только вставка ссылок.
4. Если прототип не пройдёт — согласен ли владелец на запасной вариант «Открыть в браузере».
