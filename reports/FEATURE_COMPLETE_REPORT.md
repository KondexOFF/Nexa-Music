## 2. AdBlock — ограничения и проверка

Проверено на реальном WebView2 158.0.4370.33 с временным профилем (`integration_test/ad_block_test.dart`, лог 273, PASS):
- установка распакованного uBlock Origin Lite 2026.1116.1650: принята, включена, id получен;
- повторное включение: найдено по id, второй раз не устанавливается;
- плеер YouTube с расширением ON играет (без звука) — без ошибок;
- OFF: расширение выключено по id, плеер YouTube играет;
- Remove: расширение удалено из профиля; повторный запрос по тому же id его не находит;
- контрольный запрос к YouTube не блокируется ни в одном состоянии;
- сохранение состояния (вкл., папка, id) после перезапуска — unit-тест.

`integration_test/ad_block_restart_test.dart` (лог 274, PASS), отдельный процесс:
- настоящий скачанный `uBOLite_2026.1116.1650.chromium.zip` распакован так же, как в Settings, за 12,5 с (пока идёт распаковка, Settings пишут «Unpacking...»); папка с расширением найдена, имя «uBlock Origin Lite» прочитано из локализации;
- среда WebView2 создана без расширений (первый плеер с выключенным AdBlock) → NEXA отвечает «restart», а сам WebView2 отказывает: `AddBrowserExtension failed (0x80070032)`. Значит, перезапуск действительно нужен, и NEXA о нём сообщает.


- **Правила YouTube.** Блокировка рекламы в плеере YouTube нарушает YouTube API Services Developer Policies (III.I.05–06). Возможны отзыв ключа или доступа, обнаружение блокировщика, остановка видео. Функция только для личного использования.
- **Нет гарантии.** В X1 (WebView2 157) расширение установилось, включалось и выключалось. Запрос рекламной статистики YouTube был заблокирован. Две общие рекламные адреса со страницы about:blank не блокировались. Блокирует ли оно рекламу внутри плеера YouTube, не измерить: плеер — чужой iframe.
- **Не входит в NEXA.** uBlock Origin Lite (GPLv3) не входит в NEXA и не скачивается. Вы выбираете распакованную Chromium-сборку. Обновления — вручную.
- **Применение и перезапуск.** Выключение и удаление срабатывают при следующем открытии плеера, без перезапуска. Поддержка расширений в WebView2 задаётся один раз при создании среды WebView2 в процессе. Если в этом запуске плеер уже открывался с выключенным AdBlock, то **включение требует перезапуска NEXA**: Settings говорят об этом и показывают «Restart NEXA now» (проверка — `integration_test/ad_block_restart_test.dart`, раздел 2c).
- **Профиль общий.** Расширение работает в профиле WebView2, общем для YouTube и SoundCloud.

## 2a. SoundCloud — поиск (проверка 24.11.2026)

Источники: developers.soundcloud.com — `docs/api/register-app`, блог «self-serve API keys» (18.05.2026), `docs/api/terms-of-use`, `docs/llm-context`.
- **Как работает официальный поиск.** Токен по client credentials: `POST https://secure.soundcloud.com/oauth/token`. Поиск: `GET https://api.soundcloud.com/tracks?q=…&access=playable` с заголовком `Authorization: OAuth …`.
- **Доступ.** Ключи (client id / secret) выдаются самостоятельно, но только при подписке **Artist Pro** (платная).
- **Условия API.** Результаты можно хранить только на время сессии. Нельзя объединять или проигрывать контент SoundCloud вместе с другими сервисами, нельзя менять контент и мешать рекламе; нужна атрибуция.
- **Вывод.** Даже с платным ключом поиск в NEXA противоречил бы общей очереди (несколько источников), избранному и плейлистам (хранение) и NEXA Wave. Поэтому поиск остаётся документированным ограничением; неофициальные способы (скрытые client id сайта, разбор страниц) не используются.
- **Решение для владельца (по желанию).** Если вы оформите Artist Pro и согласитесь, что найденные треки SoundCloud не попадают в избранное, историю и общую очередь, можно сделать отдельный поиск SoundCloud только с воспроизведением в виджете. Это новый CR.

## 2b. Smart Mix — как принимается решение

Только Smart Mix, только при включённом «allow» и только если **обе** песни — файлы библиотеки с готовым замером:
- **Тихий хвост:** переход заканчивается там, где кончается звук.
- **Затухающее аутро:** переход начинается там, где аутро стало на 18 дБ тише средней громкости песни.
- **Тихое начало следующей песни** (0,3–10 с): она начинается со звука.
- **Ограничения:** пропускается не больше 30 с или 15 % песни, никогда в её первой половине; тишина короче 0,5 с не пропускается. Длина перехода никогда не увеличивается. В панели Mix Engine написана причина («skips the silent end of the song» и т. п.).
- Замер делается в фоне, когда песня становится текущей или следующей (меньше 1 с на песню). Пока замера нет — обычный crossfade. Файлы длиннее 20 минут не измеряются; ошибка декодирования не повторяется в этом запуске.
- **Почему не FFmpeg.exe.** Отдельный ffmpeg.exe (LGPL) добавил бы 60–80 МБ, лицензионные условия и второй декодер. Собственный libmpv NEXA уже декодирует все форматы библиотеки. Фильтры FFmpeg в нём недоступны (лог 261), но они и не нужны: замер делает код NEXA.

## 2c. Что осталось объективно ограниченным

- YouTube: поиск только со своим ключом Data API; crossfade, фон, скачивание — запрещено условиями.
- YouTube History: без своего ключа нельзя проверить `madeForKids`, поэтому история YouTube не пишется.
- SoundCloud: поиск (раздел 2a); crossfade, Wave, скачивание — звук только в виджете.
- AdBlock: нарушает правила YouTube API; блокировка не гарантируется; обновления расширения вручную; включение после открытого без него плеера — перезапуск.
- Smart Mix: только файлы библиотеки; громкость не выравнивается; BPM и тональность не анализируются.
- Jamendo: нужен ваш client id.
- Не в плане: тексты, эквалайзер, ReplayGain, визуализаторы.
