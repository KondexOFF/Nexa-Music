## 2. Что сделано в прототипе

- Пакет `webview_flutter_windows` **1.3.0** (WebView2; рендер в Flutter Texture).
- Страница `assets/youtube/player.html` загружает официальный `https://www.youtube.com/iframe_api` и создаёт стандартный `YT.Player` с элементами управления и брендингом YouTube. Плеер не изменяется, ничего не рисуется поверх, реклама не трогается. Аудио не извлекается: звук идёт только из видимого плеера, мимо `PlaybackEngine` и Mix Engine.
- Идентификация приложения: страница открывается с виртуального хоста WebView2 `https://com.kondexoff.nexamusic` (обратная запись имени приложения). Поэтому у запросов к YouTube есть настоящий `Origin` и `Referer`, а в `playerVars` передаются `origin` и `widget_referrer`.
- Экран Settings → **YouTube prototype (E2.0)**:
  - поле ссылки (watch, youtu.be, shorts, embed, live, music.youtube.com, ID) и Play;
  - плеер 16:9 шириной во всю страницу, не меньше 480 × 270;
  - значок YouTube, ссылки «Open on YouTube», YouTube Terms и Google Privacy;
  - понятные тексты ошибок 2, 5, 100, 101 / 150, 153, «нет WebView2» и «нет интернета»;
  - когда видео выбрано, рядом всегда есть «Open on YouTube»: видео открывается в браузере по умолчанию.
- `YouTubePrototypeController`:
  - «играет один»: запуск NEXA ставит YouTube на паузу, запуск YouTube ставит NEXA на паузу;
  - сворачивание, скрытие и закрытие окна ставят YouTube на паузу;
  - уход со страницы: пауза, затем WebView2 освобождается;
  - пока последним играл YouTube, медиаклавиши управляют им, а медиапанель Windows показывает его состояние.
- Самотест (`NEXA_E20_SELFTEST`) и сценарий `tools/e2_0/e2_0_prototype_test.ps1` для автоматического прогона R1–R5 на настоящем Windows.
  - Видео в прогоне без звука; локальный «трек» — тон с громкостью 0.
  - Скриншоты делаются, только когда NEXA — переднее окно.
- `NuGet.Config` в корне репозитория. Без него сборка плагина падала: в NuGet на ПК не было ни одного источника.

Ничего не сохраняется: нет истории, плейлистов, Wave и DNA, нет ключа API. Профиль WebView2 лежит в папке данных NEXA (`<data>\webview2`), а не в Portable-папке.

### R1 — воспроизведение и ошибка 153: PASS

- Страница открыта с `https://com.kondexoff.nexamusic`; IFrame API загружен.
- Негативный контроль: та же страница без идентичности (`loadStringContent`, без настоящего origin) даёт **ошибку 153**. Значит, YouTube действительно проверяет Referer, и виртуальный хост эту проверку проходит.
- Три встраиваемых видео: `M7lc1UVf-VE`, `aqz-KE-bpKQ`, `eRsGyueVLvQ`. Все дошли до «playing», играли ≥ 3 с, ошибок нет, качество hd720 в окне 1280 × 720.
- Несуществующий ID `aaaaaaaaaaa` даёт ошибку **150**, а не 100. Текст ошибок 101 / 150 исправлен: «владелец не разрешает **или** видео больше недоступно».
- Скриптовый запуск со звуком без клика внутри страницы блокируется политикой автозапуска браузера (`onAutoplayBlocked`). Скрипт сразу показывает подсказку «нажмите play в плеере YouTube». См. раздел 7.

### R3 — медиаклавиши и SMTC: PASS (после исправления)

- WebView2 **не** создаёт свою сессию в медиапанели Windows: в обоих прогонах видна одна сессия, `nexa_music.exe`. Двух конкурирующих сессий нет.
- Прогон 1: FAIL. Пока играл YouTube, клавиша Play/Pause доходила до NEXA как «Play», и видео не вставало на паузу.
  - Причина: Windows превращает аппаратную клавишу Play/Pause в кнопку Play или Pause по состоянию сессии.
  - Сессия NEXA говорила «Paused», потому что сама NEXA молчала.
- Исправление (`c31135a`): пока последним играл YouTube, медиапанель показывает состояние YouTube («YouTube video», Playing / Paused). Когда пользователь снова запускает NEXA, панель возвращается к NEXA.
- Прогон 2:
  - YouTube играет, клавиша → YouTube на паузе, NEXA не запустилась;
  - клавиша ещё раз → YouTube снова играет;
  - играет NEXA, клавиша → NEXA на паузе, YouTube не запустился.
- «Следующий» и «предыдущий», пока последним играл YouTube, ничего не делают: в прототипе нет очереди YouTube. Очередь NEXA при этом не трогается.

## 5. Требования YouTube (проверено 2026-10-26)

- **Идентификация API-клиента** (Developer Policies III.D.1; IFrame API, ошибка 153 с июля 2025): клиент отправляет `Referer` и origin своего приложения `com.kondexoff.nexamusic`. Подтверждено на Windows: с идентичностью видео играет, без неё — ошибка 153.
- **Made for Kids** (III.E.4.10): для видео «для детей» клиенты должны отключать отслеживание. NEXA ничего не отслеживает: нет аналитики, рекламных SDK, истории YouTube и сохранения данных, плеер стандартный. Детские видео в прототипе отдельно не проверялись. В E2 правило остаётся: никакого отслеживания на стороне NEXA.
- **Обновления клиента** (III.B.1: актуальные версии API, клиент должен уметь обновляться):
  - IFrame API и плеер загружаются с YouTube при каждом открытии, поэтому всегда актуальны;
  - WebView2 Evergreen обновляется Windows;
  - у самой NEXA нет автообновления, новые версии ставятся вручную из Portable-сборки. Для личного использования этого достаточно; в E2 нужно записать процедуру обновления в документацию (E2.4).
- **Плеер, реклама, брендинг** (III.I.5–6): плеер стандартный, ничего не скрыто и не перекрыто, реклама показывается как есть. Размер ≥ 480 × 270 (RMF рекомендует 480 × 270, минимум 200 × 200).
- **Фон и аудио** (III.I.7–9): пауза при сворачивании и уходе со страницы проверена; аудио не отделяется и не смешивается с NEXA.
- **Нет встраивания** → понятная причина и «Open on YouTube» (открывается в браузере).

## 7. Известные ограничения прототипа

- **Автозапуск со звуком.** Нажатие Play в NEXA находится вне веб-страницы, поэтому браузер может не дать скрипту запустить видео со звуком. Тогда пользователь нажимает play в самом плеере YouTube; подсказка показывается. В E2.1 решить: оставить так (проще и заведомо по правилам) или запускать видео по клику внутри плеера.
- Ссылки внутри плеера (заголовок, логотип YouTube) открываются отдельным окном WebView2, а не в браузере по умолчанию. В E2.1 направить их в системный браузер. Автоматически не проверялось.
- Метрика кадров Flutter не видит кадры видео (раздел R2).
- Компьютер без WebView2 Runtime не проверялся (путь «недоступно» покрыт unit-тестом).
- Нет поиска (Data API), очереди YouTube, экрана согласия, удаления данных — это E2.2–E2.4.
- Во время прогона R3 скрипт нажимает медиаклавишу. Если в это время звучит другое приложение (например, браузер), Windows может направить клавишу туда. Во время прогонов других медиасессий не было.
