## 2. Что реально реализовано
- [x] **Медиаклавиши через Windows Media Controls (TD-06, D-018).** Глобальные `RegisterHotKey` удалены. NEXA регистрируется в системных элементах управления мультимедиа (SMTC) через WRL. Windows сам направляет медиаклавиши приложению, которое играет, поэтому браузер, Spotify и другие плееры больше не теряют клавиши. В системной панели громкости Windows видны песня, исполнитель и состояние. Кнопки Play, Pause, Next, Previous и Stop передаются в плеер. `WM_APPCOMMAND` используется только если SMTC недоступен. Сборка и запуск подтверждены; поведение с реальными клавишами — в финальной стадии (TD-16).
- [x] **Клавиатура:**
  - Space — пауза / воспроизведение;
  - Ctrl + → / ← — следующий / предыдущий трек;
  - Ctrl + ↑ / ↓ — громкость;
  - Ctrl + M — без звука;
  - Esc — выйти из поля ввода.
  
  Клавиши не мешают набору текста, а Space на кнопке в фокусе по-прежнему нажимает эту кнопку. Список сочетаний есть в Settings.

## 4. Архитектурные решения
- **SMTC вместо глобальных клавиш (D-018).** Это системный способ Windows: клавиши получает тот плеер, который играет. Реализация на WRL (без C++/WinRT и исключений) совместима с флагами сборки Flutter (`_HAS_EXCEPTIONS=0`, `/WX`). Dart-интерфейс `nexa/media_keys` сохранён.
- **Переносная папка без установщика (D-019).** Установщик требует отдельного решения по плану. VC++ runtime поставляется рядом с exe (разрешено условиями Microsoft).
- **CompanyName и ProductName не менялись.** `path_provider` строит из них путь к данным (`%APPDATA%\com.kondexoff\nexa_music`). Их смена «потеряла» бы библиотеку, плейлисты и историю.
- **Сочетания клавиш через `Focus.onKeyEvent` на корне.** Срабатывают только если событие не обработали поле ввода или кнопка в фокусе — так доступность с клавиатуры не ломается.
- **Функции E1–E4 не добавлялись.** Архитектура и границы этапов 0–6 не менялись.
