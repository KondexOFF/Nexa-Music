# NEXA Music — Master Development Plan v1.0

**Статус:** базовый план проекта, изменение только с согласия владельца.  
**Исполнитель кода:** Claude Agent.  
**Техническое ревью:** ChatGPT.  
**Владелец и окончательное решение:** KondexOff.  
**Платформа первой версии:** Windows 11 x64, персональное использование.  
**Формат разработки:** небольшие этапы с обязательной проверкой и остановкой на границе этапа.

## 1. Назначение продукта

NEXA Music — персональный, преимущественно локальный музыкальный плеер для Windows с качественной фонотекой, собственным бесконечным рекомендательным потоком **NEXA Wave**, профилем музыкального вкуса **NEXA DNA** и системой переходов **NEXA Mix Engine**.

Критерий успеха: приложение реально воспроизводит музыку, сохраняет библиотеку и настройки, помогает находить подходящие записи среди доступных источников, выглядит и ведёт себя как цельный настольный продукт. Публичный сервис сейчас **не создаём**.

### Утверждённые дизайн-референсы

- `NEXA_Design_04_Home.png` — главный экран, NEXA Wave, библиотека, очередь и нижняя панель воспроизведения.
- `NEXA_Design_04_Player.png` — полноэкранный плеер и расширенный NEXA Mix Engine.

Это ориентиры **композиции, палитры и иерархии**, а не изображения, которые нужно вставить фоном. Все кнопки, панели и элементы должны быть настоящими виджетами. Если на макете есть визуальная неоднозначность, приоритет у описания функций в настоящем плане и удобства использования.

### Визуальные правила

- Фон: графитовый `#111319`, мягкие тёмно-синие панели, светлый текст `#F0EFEB`.
- Основной акцент: приглушённый лавандовый `#AD9AFF`; коралловый — для обложек и визуализации переходов, не для всех кнопок сразу.
- Сетка 8 px; примерные размеры: боковая навигация 220 px, нижний плеер 80–88 px, необязательная правая панель 275–345 px.
- Чёткая иерархия, достаточный контраст, никаких неоновых рамок вокруг каждого блока, чрезмерных теней и гигантских декоративных баннеров.
- Главная страница: компактная волна, подборки, недавно прослушанное, очередь. Экран Now Playing: обложка, трек, таймлайн, управление, очередь, Mix Engine.
- Адаптация для ширины от 1280 до 1920 px. При малой ширине второстепенные правые панели сворачиваются; интерфейс не обрезается.
- В первой версии допустим английский текст как в референсах; строки хранить централизованно для будущего перевода на русский.

## 2. Функциональные границы

### Обязательно для персональной версии 1.0

1. Локальные MP3/FLAC/WAV при поддержке выбранного аудиодвижка; папки, метаданные, обложки, поиск.
2. Фонотека, избранное, собственные плейлисты, очередь и история прослушиваний.
3. Воспроизведение, пауза, перемотка, громкость, следующий/предыдущий трек, повтор и перемешивание.
4. NEXA Mix Engine: регулируемый Crossfade (0–12 с), Gapless, в дальнейшем осторожный Smart Mix.
5. NEXA DNA: короткий первоначальный выбор жанров и исполнителей; управление предпочтениями.
6. NEXA Wave: персональная непрерывная очередь из **доступных** треков, основанная на явных оценках и разрешённой истории прослушиваний.
7. Локальные настройки и данные, пауза обучения, удаление истории и режим «не учитывать эту сессию».
8. Впоследствии: Audius и Jamendo через их официальные API, при соблюдении условий конкретного источника и разрешений на воспроизведение.
9. Рабочая Windows-сборка, руководство по запуску, тесты и финальная проверка.

### За рамками 1.0, без отдельного согласования НЕ делать

- Сервер для других пользователей, регистрацию, синхронизацию между аккаунтами, подписки, рекламу, публичный релиз.
- Android/iOS-порт во время Windows-этапов; архитектуру можно делать переносимой.
- Интеграцию с Яндекс Музыкой или копирование её закрытого рекомендательного алгоритма.
- Извлечение, скачивание, запись, обход DRM или смешивание аудио Spotify. Наличие Spotify Premium не даёт таких прав. В дальнейшем допустимы обычные ссылки «Открыть в Spotify»; Spotify API не является источником аудио NEXA.
- Использование Spotify Content/API для обучения или профилирования музыкального вкуса.
- Генеративный ИИ, серверные нейросети, автоматическую загрузку нелицензированной музыки, скрытую телеметрию.
- DJ-эффекты, эквалайзер, ReplayGain, синхронизацию текста песен и визуализаторы до отдельного утверждения после основной версии. Если они нужны, оформить следующую версию плана.

**Важно:** личный характер проекта не отменяет авторских прав и условий музыкальных сервисов.

## 3. Технический фундамент

**Предпочтительный стек:** стабильный Flutter/Dart для Windows, Riverpod для состояния, SQLite/Drift для локальной базы. Аудиодвижок выбрать в этапе 0 **после работающего прототипа на Windows** (кандидат `media_kit`); не фиксировать совместимость только на основании документации. Локальный импорт — через системный выбор файлов/папок и сохранение устойчивых путей либо явное копирование в библиотеку по выбору пользователя.

### Границы модулей

```text
lib/
  app/                       # точка входа, тема, навигация
  core/models/               # Track, MusicSource, ListeningEvent, TasteProfile
  core/database/             # SQLite и миграции
  core/audio/                # единый интерфейс PlaybackEngine
  features/library/          # импорт, поиск, избранное, плейлисты
  features/player/           # плеер, очередь, медиа-кнопки
  features/mix_engine/       # Crossfade, Gapless, Smart Mix
  features/nexa_dna/         # первоначальный профиль вкуса
  features/nexa_wave/        # генерация персональной очереди
  features/settings/         # приватность и настройки
  integrations/              # отдельные адаптеры аудиоисточников
test/
docs/
```

Структура — ориентир, а не разрешение плодить пустые папки. Каждый модуль создавать только когда он нужен соответствующему этапу.

### Минимальные доменные модели

- `Track`: внутренний id, `source`, `sourceTrackId`, название, артист, альбом, длительность, обложка, путь/URI, доступные права воспроизведения, необязательные теги.
- `MusicSource`: поиск/список доступных треков; получение метаданных; способ разрешённого воспроизведения. Не предполагать, что все источники разрешают скачивание или смешивание.
- `ListeningEvent`: трек, время, длительность фактического прослушивания, причина пропуска/завершения, режим прослушивания. Записывать **только при согласии пользователя**.
- `TasteProfile`: явно выбранные жанры/исполнители, веса предпочтений, исключения, время изменения; доступен сброс.
- `MixSettings`: режим, секунды перехода, разрешение на интеллектуальную коррекцию, исключения для альбомов.

## 4. План разработки — строго по порядку

**Правило перехода:** Claude выполняет **только текущий разрешённый этап**, присылает отчёт, затем **останавливается**. Следующий этап — только после сообщения владельца «Этап N принят, начинай N+1». Ни один из нижних пунктов не разрешает самовольно начать все этапы за один запуск.

### Этап 0 — Диагностика и безопасная основа

**Сделать:**

1. Осмотреть текущую папку проекта, существующие файлы и Git; ничего не перезаписывать без необходимости.
2. Проверить `flutter --version`, `flutter doctor -v`, наличие компонентов Windows desktop (Visual Studio C++), доступность тестовой машины.
3. Создать минимальный Flutter Windows-проект только если в выбранной папке ещё нет проекта.
4. Проверить один демонстрационный локальный аудиофайл, права на который есть у пользователя, через выбранный Windows-аудиодвижок: открытие, play/pause, seek, set volume. Не добавлять в репозиторий защищённые треки.
5. Зафиксировать версии SDK и зависимостей, добавить `.gitignore`, базовый `README.md`, `docs/DECISIONS.md`, безопасный локальный Git-коммит при наличии разрешения.

**Приёмка:** проект запускается на Windows, аудиопрототип действительно играет файл либо есть точный воспроизводимый блокер; `flutter analyze` и `flutter test` запускаются и их результаты зафиксированы. Если окружение не готово, остановиться и запросить решение, не имитировать успешную сборку.

### Этап 1 — Дизайн-система и каркас двух экранов

**Сделать:** тема, токены, адаптивный каркас; Home, NEXA Wave hero, лента подборок, библиотечная таблица, Up Next, нижний плеер; отдельный экран Now Playing и место под Mix Engine по двум PNG-референсам. Демо-данные допустимы, но должны быть явно помечены, а не выданы за реальные.

**Приёмка:** макеты выглядят цельно на 1280×720 и 1920×1080, нет переполнений или неактивных кнопок, которые выглядят работающими; навигация между страницами функционирует. Сделать скриншоты и сравнить с дизайн-референсами.

### Этап 2 — Локальная библиотека и база данных

**Сделать:** импорт файла/папки, индексация поддерживаемых форматов, метаданные, обложки, поиск, избранное, плейлисты, обновление изменённой папки, SQLite-миграции. Файлы не копировать молча и не удалять из исходных папок.

**Приёмка:** после перезапуска сохраняются 30+ импортированных треков, плейлист и избранное; пропавший или недоступный файл показывает понятную ошибку; дубликаты не множатся при повторном сканировании.

### Этап 3 — Полноценный Playback Engine

**Сделать:** реальный звук из библиотеки, очередь, play/pause, seek, shuffle/repeat, переключение треков, громкость, корректное закрытие ресурса; где доступно — мультимедийные клавиши Windows и фоновое воспроизведение.

**Приёмка:** ручной сценарий 20 последовательных треков, пауза/возобновление, повтор/перемешивание, смена устройства вывода либо понятная обработка ограничения движка; нет двух непреднамеренно играющих треков.

### Этап 4 — NEXA Mix Engine

**Сделать в порядке:**

1. **Gapless** — отсутствие добавочной паузы между соседними совместимыми треками, без наложения.
2. **Crossfade** — 0–12 секунд, предзагрузка следующей композиции, одновременное управление громкостью двух декодеров, плавная кривая equal-power; диапазон и состояние сохраняются.
3. **Smart Mix v1** — только простой объяснимый подбор времени перехода по доступной длительности, тишине и уровню сигнала. Согласование BPM/тональности **не объявлять реализованным**, пока реально не разработано и не протестировано.
4. Видеографика/волны перехода являются отражением состояния, а не заменой реальной звуковой функции.

**Приёмка:** на разрешённых локальных тестовых файлах переход слышен без резкого обрыва и клиппинга; 0 секунд отключает наложение; режим Gapless не смешивает части концертных/альбомных треков; при невозможности предзагрузки — безопасный обычный переход. Протестировать несколько разных форматов и короткие записи. Сторонние источники смешивать только когда условия это позволяют.

### Этап 5 — NEXA DNA и NEXA Wave v1

**Сделать:** первичный выбор жанров/исполнителей (с возможностью пропустить), лайк/дизлайк, локальная история прослушиваний по согласию, режим «не учитывать сессию», управление «знакомое ↔ открытия», объяснение «почему предложен этот трек». Собственный простейший ранжировщик на основе тегов, предпочтений, повторов, дослушиваний и пропусков; отрицательный сигнал быстрого пропуска слабее явного дизлайка. Исключать недавно повторявшиеся композиции и недоступные источники.

**Приёмка:** предпочтения изменяют очередь на воспроизводимом тестовом наборе; дизлайк действительно исключает трек; в приватной сессии ListeningEvent не сохраняется; всё работает без интернета на локальной библиотеке; настройки можно сбросить.

### Этап 6 — Разрешённые онлайн-каталоги

**Сделать:** отдельные адаптеры Audius и Jamendo через официальные API, поиск и воспроизведение только разрешённых треков, указание источника, обработку отсутствия сети/лимитов, учёт правил скачивания и использования. Не смешивать аудио источника, если это запрещено условиями. Встроенные ключи не помещать в репозиторий.

**Приёмка:** поиск выдаёт только реально доступные результаты, треки корректно запускаются, недоступность сети не ломает локальный режим, воспроизведение соблюдает ограничения каждого провайдера.

### Этап 7 — Полировка, производительность и выпуск персональной версии

**Сделать:** доступность клавиатурой, ошибки, пустые состояния, отзывчивость, настройки, отсутствие тяжёлых ненужных эффектов, тесты, документация, воспроизводимая Windows-сборка (`flutter build windows`). Упаковка в установщик только после отдельного одобрения формы распространения; локальную `.exe`/build допускается создать в рамках этапа.

**Приёмка:** сборка на Windows успешна, приложение перезапускается с сохранённой базой, локальное прослушивание продолжает работать без сети, ключевые сценарии пройдены; закрыты критические ошибки. Оставшиеся дефекты явно перечислены.

## 5. Контроль запрета на отклонения

1. **Не менять этот Master Plan**, список этапов, объём этапа, лицензирование или стек без отдельного сообщения владельца. Записывать предложение в `docs/CHANGE_REQUESTS.md`, но не выполнять до согласования.
2. **Не начинать следующий этап**, даже если остались токены, время или «легко сделать». Остановиться и сдать отчёт.
3. Новые функции, визуальные редизайны, SDK, большой рефакторинг вне текущего этапа — только через Change Request с причиной, последствиями, рисками и тестами.
4. Исправлять только проблемы, мешающие текущему этапу, сохраняя пользовательские файлы и изменения. Никаких разрушительных команд, удаления незнакомых данных, переписывания чужого кода или принудительных Git-reset.
5. Не добавлять заглушки, которые притворяются реальной музыкой, алгоритмом или проверенными тестами. Демо явно обозначать.
6. Не копировать чужой интерфейс пиксель-в-пиксель: референсы задают собственный стиль NEXA. Не копировать код, иконки и графику сторонних приложений без права использования.
7. Не отправлять приватную историю, локальные файлы или секреты во внешние службы. Секреты в отчётах скрывать.
8. При техническом блокере или спорном решении **остановиться, описать варианты и запросить выбор**, не обходить ограничения молча.
9. Для каждого этапа сохранять перечень файлов и конкретные результаты тестирования. Не писать «всё работает», если этого не проверяли.
10. Если дизайн противоречит доступности или реальному поведению Windows, оформить минимальное отклонение с объяснением и спросить разрешение.

## 6. Обязательные проверки в конце каждого этапа

- `flutter analyze` — привести весь вывод ошибок/предупреждений и код завершения.
- `flutter test` — количество и результаты тестов, код завершения.
- По этапам с Windows UI — `flutter run -d windows` с фактическим результатом и скриншотом.
- По этапу 7 — `flutter build windows` и путь к артефакту.
- Минимум три ручных сценария, прямо относящихся к текущему этапу.
- Проверка `git status`/diff: отсутствуют неожиданные изменения, секреты, большие музыкальные файлы и посторонние зависимости.

Если команда недоступна, указывать **NOT RUN**, точную причину и действие, необходимое для проверки. Не трактовать это как PASS.

### E2.6 — мини-плеер YouTube

- **Сделать:**
  - Один `WebviewController` на всё приложение, размещённый на уровне оболочки (shell), а не страницы. Переходы Home / Library / Discover / Wave не перезагружают видео; позиция сохраняется.
  - Состояния:
    - развёрнутое (страница YouTube);
    - компактная панель в углу, 16:9, не меньше 200 × 200 по правилам YouTube — то есть около 356 × 200;
    - закрыто.
  - Кнопки «развернуть / свернуть / закрыть» — рядом с плеером, не поверх него.
  - Размер и элементы управления:
    - официальный плеер никогда не меньше 200 × 200 (Required Minimum Functionality);
    - в компактном режиме проверяется, что элементы управления YouTube видны и нажимаются (play, громкость, полный экран, логотип);
    - если при каком-то размере они обрезаются, этот размер не используется.
  - Переключение разделов не перезагружает плеер, не теряет позицию видео и не сбрасывает очередь.
  - Режим «мини-окно»: всё окно NEXA сжимается до маленького окна поверх других приложений с одним плеером. Это видимый плеер, а не фоновый.
  - `PlaybackArbiter`, медиаклавиши, медиапанель Windows и пауза при сворачивании окна сохраняются.
- **Исследовать:** отдельное PiP-окно ОС (многооконность Flutter для Windows) и PiP браузера. PiP самого `<video>` недоступен: видео находится в чужом домене (iframe YouTube). Если отдельное окно Flutter окажется нестабильным, основной вариант — режим «мини-окно».
- **Приёмка:**
  - переходы между разделами не прерывают и не перезапускают видео, позиция и очередь сохраняются;
  - в компактном размере все элементы управления YouTube видны и работают;
  - панель не перекрывает элементы плеера YouTube;
  - сворачивание всего окна NEXA — пауза;
  - мини-окно видимо поверх других приложений и управляется медиаклавишами;
  - NEXA и YouTube никогда не звучат вместе.
- **Тесты:**
  - widget — состояния, размеры не меньше 200 × 200, переходы без dispose контроллера, очередь не меняется при переходах;
  - скриншоты компактного и развёрнутого состояний (видимость элементов YouTube);
  - Windows integration — переход между разделами, позиция видео не сбрасывается;
  - ручная проверка.

### E2.7a — Избранное, плейлисты и закладки

- **Сделать:**
  - Единая модель записи: источник (`local / audius / jamendo / youtube / soundcloud`) + ID у источника + сохранённые поля.
  - Избранное, пользовательские плейлисты: создать, переименовать, удалить, изменить порядок, удалить запись. Повторное открытие любой записи.
  - Миграция базы данных — безопасная:
    - перед миграцией автоматически создаётся резервная копия базы с датой в папке данных NEXA;
    - миграция выполняется в одной транзакции;
    - после миграции проверяется, что число плейлистов, их записей и избранного не изменилось;
    - при ошибке изменения откатываются, база восстанавливается из копии, NEXA запускается со старыми данными и показывает понятное сообщение;
    - в Settings есть ручное восстановление из резервной копии.
  - YouTube:
    - хранится закладка: video ID, ссылка и имя, которое задал пользователь;
    - полученные от YouTube данные (название, канал, миниатюра) хранятся с датой получения и обновляются не реже чем раз в 30 дней (Developer Policies III.E.4.c). Если обновить нельзя, они удаляются, а остаются ID и имя пользователя;
    - видео не скачивается.
  - Недоступные записи (удалены, закрыты, нет сети) показываются серыми и пропускаются, плейлист не ломается.
- **Приёмка:** резервная копия создаётся до миграции; существующие плейлисты и избранное сохранены полностью; сбой миграции восстанавливает прежние данные; всё сохраняется после перезапуска; переименование, удаление и порядок работают; недоступная запись не ломает воспроизведение; записи старше 30 дней обновляются или очищаются.
- **Тесты:**
  - unit — миграция с копией базы v3 (число плейлистов и записей до и после), искусственный сбой миграции → восстановление из копии, правило 30 дней;
  - widget;
  - Windows integration — перезапуск с той же базой.

### E2.7b — история, Recently Played, Continue Listening

- **Сделать:**
  - Общий переключатель истории (ON/OFF). Local, Audius и Jamendo работают как раньше, независимо от YouTube.
  - Отдельный переключатель «Локальная история YouTube», по умолчанию выключен.
  - Для YouTube запись делается, только если известен статус видео:
    - статус проверяется через `videos.list part=status` (`madeForKids`), это 1 единица квоты на 50 видео;
    - видео «для детей» никогда не записываются в историю и не продолжаются с позиции (Developer Policies III.E.4.j: для них отслеживание выключено);
    - без ключа статус неизвестен — запись не делается, и это объясняется в настройках.
  - Recently Played и Continue Listening (с позиции) для разрешённых записей; очистка истории.
- **Приёмка:** выключенная история ничего не пишет; детское видео не записывается; YouTube без ключа не записывается и это объяснено; локальная история не зависит от YouTube.
- **Тесты:** unit — правило записи, Made for Kids, без ключа; widget; Windows integration.

### E2.8 — единая очередь

- **Сделать:**
  - Очередь из записей любых источников: добавить, удалить, изменить порядок; следующий / предыдущий, повтор, перемешивание.
  - Восстановление очереди после перезапуска.
  - `PlaybackArbiter`:
    - запись с потоком играет через `PlaybackEngine`;
    - запись YouTube — в одном видимом плеере (мини или развёрнутом), следующая начинается по событию «видео закончилось»;
    - никакого скрытого воспроизведения и отдельного аудиопотока YouTube.
  - Mix Engine (Crossfade) — только между записями с правом обработки звука. Переход на YouTube и с YouTube — обычный, без смешивания.
  - Если WebView2 не даёт автоматически запустить следующее видео YouTube (блокировка автозапуска), показывается заметная кнопка «Продолжить» в мини-плеере и в очереди. Очередь ждёт пользователя: не зависает и не перескакивает дальше.
  - Если запись нельзя воспроизвести (видео не встраивается, удалено, нет сети), показывается причина. Переход к следующей записи — только с этим сообщением и видимой отметкой в очереди, никогда молча.
- **Приёмка:** смешанная очередь Local → YouTube → Jamendo играет по порядку; повтор, перемешивание и восстановление работают; при свёрнутом окне YouTube стоит на паузе, и очередь не идёт дальше; при блокировке автозапуска видна кнопка «Продолжить», очередь не зависает; пропуск записи всегда объяснён.
- **Тесты:** unit — арбитр и очередь с поддельными плеерами, блокировка автозапуска → кнопка «Продолжить», недоступная запись → сообщение и отметка; Windows integration — смешанная очередь.
